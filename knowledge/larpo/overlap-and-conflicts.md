# Overlap and conflicts: Larpo doctrine vs engine notes

Method: read all of the Larpo material (design-intelligence, saas-visual-systems, anti-ai playbook, design-generation-refresh incl. feedback ledger, 2026-09-01 divergence note, x-post synthesis, both playbooks, context/, decisions/, four concept folders incl. PNGs and CSS) and grepped `knowledge/`, `system/directions/axes.json`, `tools/thresholds.json` and `tools/*.mjs`/`build_index.py` for each topic. Rule IDs refer to the files in this folder (LDP, LHS, LSV, LAI, LBC). Nothing was changed outside `knowledge/larpo/`; resolutions below are recommendations for the engine owner (several need edits to `tools/thresholds.json`, `CLAUDE.md` or other notes that were out of scope).

Important context: the engine has already absorbed a lot of Larpo's research. `knowledge/web/anti-ai-slop.md` cites the Larpo playbook and the 2026-09-01 note and says it "does NOT repeat their taxonomy"; `anti-ai-slop-detector.md` encodes Larpo's batch rejection rules (B-AXIS, B-ROW, B-TRANSPLANT, C-1 grayscale + 24px blur, C-5 25% legibility); `system/directions/axes.json` is derived from the 2026-09-01 matrix. So the real value of this folder is what the engine had NOT absorbed: the founder verdict ledger, the publisher/subject boundary, the X delivery contract, brand constraints and caption doctrine.

## 2. What we have that Larpo lacks

- **Measurement**: teardown medians (56 px H1 at 1440, 48-64 band, 104 px section padding, CTA height 38-48 px, tracking), `tools/thresholds.json`, `check.mjs`, ledger fingerprint with 8 axes, `score.mjs`, evals. Larpo's rules are almost all `visual` or prose; its only numbers are the 56-84 px band, 2:1 spacing, 45-75 ch, 22/30 and 3/5 cluster thresholds.
- **Detector spec** with page-level and batch-level tells, Krebs/Impeccable tiers (0-1 / 2-3 / 4+), thresholds for cream ground, crushed tracking (<= -0.05em), oversized H1 (>= 72 px and >= 40 chars), display ceiling 96 px.
- **Copy system**: CW rules, em-dash density, tricolon/negative-parallelism lint, headline patterns, generic-CTA fail list.
- **Motion system**: duration/easing/spring tokens, `prefers-reduced-motion` map, WCAG 2.2.2/2.3.1/2.3.3, perf/INP, library notes (Motion, GSAP, CSS native).
- **Colour toolchain**: OKLCH recipes, `palettes.json`, `palette-recipes.md`, contrast tooling; Larpo only says "use OKLCH, verify pairs".
- **Type catalogue**: `font-catalogue.md/json` with licences and pairings; Larpo has a 10-font starting table.
- **Book-derived fundamentals** (UI Pedia, Dos and Don'ts, psychology of user, what-to-do-next), CRO evidence grading (`landing-page-anatomy`), section library, teardowns of real sites, art-direction moves M01-M60, design-system token architecture, coss ui stack conventions.
- **Cross-batch tooling**: the dealer (`deal.mjs`), diversity gate (`ledger.mjs similar`), pairwise fingerprint distance.
- **Reserved-identifier discipline** for sample data (example.com/.test, 555-0100..0199, RFC 5737 IPs).

## 4. Biggest conflicts to decide first

1. **C7**: "divergence beats polish" vs the founder's R1 update (polished default-modern; novelty gestures rejected). This changes the dealer.
2. **C1/C2/C10**: Larpo-owned surfaces need a brand-owned exemption layer (Geist, lowercase, no em dash, no hover lift, no gradients); the engine's checks currently treat these as tells.
3. **C6**: scope-locked single desktop still versus the engine's mobile-and-all-states pipeline.
4. **C4/C5**: headline size/tracking bands and canvas sizes disagree within Larpo itself; the engine floors should win with a 1920-canvas exception.

## 5. Judgement notes

- [engine note] Talaya and Vouch (no verdict) and Take/Mise (better received) all share a left-headline/right-support/wide-product-stage skeleton when viewed as PNGs, which is the same family resemblance the 2026-09-01 note describes. The founder accepted Take and Mise in spite of that, so the skeleton alone is not the whole story: whole-frame product-world coherence appears to matter more.
- [engine note] The X post demotions (posts 09, 15, 16, 19 moved to `duds/` on "Rokas's instruction to move entries not worth recommending") are verdicts on other people's reference posts, selected by an agent-computed reach ratio. They are NOT in `seed-verdicts.json` because the specific selection was agent-made; the 4 caption-pattern entries there are limited to rules stated as Rokas's own.
- Evidence limits stated by the team: reach multiple is a proxy on single observations; no true flop in the collection; timing claims unsupported (7 timed posts).
- Not read in depth: `03-curated-resource-library.md` (418 entries), `04-github-repository-atlas.md` (272 repos), `09-tools-and-repository-atlas.md`, `sources.md` files, `context/telegram-bot.md` (35 KB bot spec, only relevant for lowercase enforcement "in code"), `state/2026-08-22-x-competitive-research.md`.
