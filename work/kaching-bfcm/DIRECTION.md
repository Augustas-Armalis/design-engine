# Kaching BFCM hero: direction (2026-10-19)

Brief: Kaching homepage hero (top half only; app tabs + storefront demos stay below) promoting the BFCM offer to
Shopify merchants. One action: install / explore apps. Proof needed: the 1x / 1.9x / 3.8x revenue comparison (Kaching
data, footnoted) and the 0 / 30 / 35 / 40% tier ladder. Bound system: Kaching's own (site DESIGN-SYSTEM.md), not a
house system: this is an existing brand, so divergence rules yield to brand consistency.

Round 1 verdict (founder): split card with rolling figure + bars "not nice and not our brand enough, too stupid";
"do the titles better".

Hero class: product proof (the data is the product's promise).

Concept: **a dithered skyline**. Kaching's live pixel dither (its brand material) becomes the chart itself: columns
of live dither rise from the hero floor, one per app count, as tall as the extra revenue those stores earn. The
discount ladder rides along the floor as white tags inside the columns, so one picture says "more apps, more revenue,
bigger discount".

Reference triad
- Structure: founder rule "visual in the right column, pushed right and down so it bleeds off the frame edge, top
  roughly level with the headline" (founder-taste, Tideline r2) -> columns grow from the hero's floor line.
- Type/identity: Kaching's own homepage hero: tilted app icon inline before a gradient app name -> the BFCM title
  carries a fan of the four app icons inline before the gradient "with Kaching".
- Material/motion: Kaching affiliate simulator (dithered bars) + "pixel develop" entrance -> columns develop from the
  floor up as the one conceptual reveal; the tag tour (1 -> 4+ apps) is the only loop.

Owned decisions: dither-as-chart; icon fan in the title; tags as the offer ladder on the floor; merged 3+ column
carrying two tiers (honest grouping of the data); hairline floor = hero/stage boundary.

Overrides
- override: HC-05 (5 units) because the footnote is a legal/honesty requirement; it is set as a quiet 12px line.
- override: no-chart-as-hero-visual (product UI preferred) because the offer *is* the data; there is no product
  screen for a discount.
